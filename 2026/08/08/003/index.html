Counting Rooms

题目大意：n×m 的地图上 # 表示墙、. 表示地板，可以上下左右走。房间指由地板组成的、四方向连通的连通块，求一共有多少个房间。

解题思路：遍历整张地图，每遇到一个没被处理过的地板格，就说明发现了一个新房间，答案加 1；然后用 DFS 把这个格子所在的整个连通块"染掉"（代码里直接把地板改成 #，等价于标记已访问），并继续向四个方向递归。每个格子最多被访问常数次，复杂度 O(nm)O(nm)O(nm)，地图最大 1000×10001000\times10001000×1000，完全够用。

Labyrinth

题目大意：n×m 的迷宫，A 是起点、B 是终点、# 是墙。每步可上下左右移动到非墙格子，求从 A 到 B 的最短路：有解先输出 YES，再输出路径长度和由 L/R/U/D 组成的移动方向串；无解输出 NO。

解题思路：BFS 天然按"步数递增"的顺序扩展，第一次到达 B 时步数一定最短。用 previous[i][j] 记录每个格子从哪个格子走来，用 last_letter[i][j] 记录这一步对应的方向字符。BFS 结束后若 B 未被访问则无解；否则从 B 沿 previous 一路回溯到 A，把收集到的方向串 reverse 即可。每个格子入队至多一次，复杂度 O(nm)O(nm)O(nm)。

Building Roads

题目大意：n 个城市、m 条已经建好的路（每条连接两个城市）。现在可以任意在两个城市之间新建道路，要求用最少的新路让整个图连通，输出最少新路数，并输出要修的路。

解题思路：当前图被分成若干个连通块，每在两个连通块之间修一条路就能把它们合二为一，所以最少新路数 = 连通块数 −1-1−1。代码用并查集实现：读入每条边时 merge(u,v)，最后把所有点的 get(i) 去重放进 set，s.size()-1 就是答案；输出方案时依次在 s 中相邻的两个代表城市之间各修一条路即可。复杂度近似 O((n+m)α(n))O((n+m)\alpha(n))O((n+m)α(n))。

Message Route

题目大意：n 台电脑、m 条双向网线连接。问能否从 1 号走到 n 号，若能输出最短路径上的电脑数量以及路径上的电脑编号，否则输出 IMPOSSIBLE。

解题思路：从 1 号做 BFS，parent[y] 记录 y 是由谁首次扩展到的。若 n 始终未被访问则无解；否则从 n 沿 parent 一路回溯到 0（1 号点的 parent 为 0，作为终止哨兵），再 reverse 就是最短路径。每条边至多遍历一次，复杂度 O(n+m)O(n+m)O(n+m)。

Building Teams

题目大意：n 个学生、m 对朋友关系，朋友之间不能分到同一队。问能否把所有人分成两队，能则输出每个学生的队号（1 或 2），否则输出 IMPOSSIBLE。

解题思路：把学生看成点、朋友关系看成边，问题等价于判断这个图是不是二分图。用 DFS 给每个点染色：起点染 0，相邻点染成相反颜色（color ^ 1）。如果某个点与它已染色的邻居颜色相同，说明出现"奇环"，无法二分，标记 f = 0 输出 IMPOSSIBLE。注意图可能不连通，要对每个未访问点分别染色。复杂度 O(n+m)O(n+m)O(n+m)。

Round Trip

题目大意：无向图，找一条至少经过 3 个不同顶点、能回到起点的环，输出环上的顶点序列；不存在则输出 IMPOSSIBLE。

解题思路：DFS 过程中若当前点 u 遇到一个"已经访问过但不是父节点"的邻居 v，说明出现了一条回边，v 在 DFS 树上正是 u 的祖先，于是找到环：令 s = v（环顶）、t = u（当前点），再从 t 沿父指针 p[i] 回跳到 s，路径就是环。第一次找到就停止，避免多输出。每个点访问一次，复杂度 O(n+m)O(n+m)O(n+m)。（p、vis 等数组及递归 dfs 需定义在 solve() 外。）

Monsters

题目大意：n×m 的迷宫里有你（A）和若干怪物（M）、墙（#）。你和怪物每步同时上下左右移动一格，求能否在到达任意边界格（最外圈）之前不被怪物追上：能则输出 YES、步数和移动方向串，不能则输出 NO。

解题思路：关键结论：一个格子能安全经过，当且仅当你比所有怪物都更早到达它。先用多源 BFS 从所有怪物同时出发，算出每个格子最早被怪物占领的时间 tim[i][j]；再以起点做 BFS，只有满足 tim[nx][ny] > nt（怪物到得更晚）的格子才允许走进去，并用 fa 记录前驱。一旦走到最外圈格子就输出路径。若起点本身就在边界，直接输出 YES。每个格子最多入队常数次，复杂度 O(nm)O(nm)O(nm)。

Shortest Routes I

题目大意：n 个城市、m 条单向航线，每条从 a 到 b、费用 c。求从 1 号城市出发到每个城市的最短距离（不可达的城市距离保持初始极大值）。

解题思路：单源最短路用 Dijkstra。用小根堆（priority_queue 配 greater）每次取出当前距离最小的点：若堆里的距离已经不比 dist[x] 小（dist[x] < d）说明这个状态已过时，跳过；否则用它松弛所有出边，更新成功就重新入堆。距离可能很大，用 ll 存储、初值设为 101810^{18}1018。每个点至多入堆 m 次，复杂度 O((n+m)log⁡n)O((n+m)\log n)O((n+m)logn)，对 n≤105n\le10^5n≤105、m≤2×105m\le2\times10^5m≤2×105 足够。

High Score

题目大意：n 个房间、m 条单向隧道，每条隧道走过后分数变化可正可负，可以重复走同一条隧道。求从 1 号到 n 号能获得的最大分数；若分数可以无限增大（存在一个从 1 出发且能回到 n 路上的正权环）则输出 -1。

解题思路：最长路问题。把每条边的分数取负，就变成求最短距离与判负环，交给 Bellman-Ford。注意干扰项：即使图中存在负环（原图正环），若它走不到 n，也不应输出 -1。因此先用 BFS 筛出**同时满足「从 1 可达」和「能到达 n」**的点集 included，只在它们之间的边上做松弛；若第 n 轮仍能松弛，说明存在会影响答案的负环，输出 -1，否则 -distance[n] 就是最大分数。复杂度 O(nm)O(nm)O(nm)。

Flight Discount

题目大意：从 1 号到 n 号的带权有向图，可以把恰好一条边的权值减半，求最小总花费。

解题思路：拆点分层最短路。把每个点拆成两层：第一层（1~n）表示还没用折扣，第二层（n+1~2n）表示折扣已经用过。建边规则：第一层内部、第二层内部都连原价边（a→b、n+a→n+b），第一层的 a 到第二层的 n+b 连一条半价边 c/2（用它就相当于在 a→b 这一步用掉折扣）。这样在 2n2n2n 个点上跑 Dijkstra，distance[2n]（到达 n 且折扣已用）就是答案。复杂度 O((n+m)log⁡n)O((n+m)\log n)O((n+m)logn)。

Cycle Finding

题目大意：有向带权图，判断是否存在负环（边权和为负的环），若存在则输出其中一个负环的顶点序列。

解题思路：Bellman-Ford 松弛 n 轮。若第 n 轮仍有一条边 from→to 能松弛成功，说明 to 处于（或可达）负环，记录最后一次被松弛的终点 path_end。然后从 path_end 沿前驱 previous 不断回跳，用 visited 记录访问标记，第一次回到已访问过的点就说明进入了环，把这一段的顶点序列反转后从环的起点输出到再次出现起点为止即可。复杂度 O(nm)O(nm)O(nm)。

Flight Routes

题目大意：求从 1 号到 n 号的前 k 条最短路长度。可以重复经过城市，走的路线不同就算不同（同一条边路径顺序不同也算不同）。

解题思路：改造 Dijkstra 求第 kkk 短路：由于边权非负，小根堆出队的顺序天然按距离递增，每个点出队第 ccc 次就得到它的第 ccc 短距离。因此不设"已访问"标记、也不做距离去重，直接把所有扩展压进堆，只限制每个点最多出队 k 次（visited[x] >= k 就跳过）。终点 n 每次出队时把距离记进 dist[visited[n]]，最终 dist[0..k-1] 就是前 k 短路径。复杂度 O(kmlog⁡m)O(km\log m)O(kmlogm)，题目保证 k≤10k\le10k≤10。

Course Schedule

题目大意：n 门课程、m 条先修关系，每条 a b 表示必须先修完 a 才能修 b。求一个合法的学习顺序；若不存在（先修关系成环）则输出 IMPOSSIBLE。

解题思路：拓扑排序（Kahn 算法）。统计每门课的入度 in_degree，把所有入度为 0 的课加入队列；每次取出队首 x，删除它的全部出边 x→y（即 y 的入度减 1），若 y 入度变为 0 也入队。若最终取出的课程数不足 n，说明图中存在环，先修关系矛盾，输出 IMPOSSIBLE；否则取出顺序就是合法学习顺序。复杂度 O(n+m)O(n+m)O(n+m)。

Longest Flight Route

题目大意：n 个城市、m 条单向航线，保证图是 DAG。求从 1 号到 n 号、经过城市最多的路径，输出经过的城市数和路径；若 1 号到不了 n 则输出 IMPOSSIBLE。

解题思路：记忆化搜索 DP。longest[x] 表示从 x 出发到 n 最多还能经过多少个城市（含 x 自己），next_city[x] 记录最优的下一步。边界是 f(n)=1；对每个后继 y，longest[x] = max(longest[y]+1) 并同步更新 next_city[x]。若 f(1) < 0（搜不到 n）则无解；否则先输出 f(1)，再沿 next_city 一直走到 0 为止。因为图是 DAG，递归不会成环，记忆化安全。复杂度 O(n+m)O(n+m)O(n+m)。（longest、next_city、ready 等数组与递归 f 需定义在 solve() 外。）

Game Routes

题目大意：DAG 上从 1 号到 n 号一共有多少条不同路径，答案对 109+710^9+7109+7 取模。

解题思路：拓扑序 DP。dp[u] 表示从 1 到 u 的路径数，初值 dp[1]=1。代码用 Kahn 的方式按拓扑序处理：a[i] 记录入度，入度为 0 的点入队；取出 u 时把 dp[u] 累加到每个后继 v（dp[v]=(dp[u]+dp[v])%mod），并在 v 的入度降为 0 时入队。由于拓扑序保证处理 u 时它的所有前驱都已算完，最后 dp[n] 就是答案。复杂度 O(n+m)O(n+m)O(n+m)。（G、dp、a 等数组需定义在 solve() 外。）

Investigation

题目大意：从 1 号到 n 号，求四个量：最小花费、达到最小花费的路径条数、这些最短路径中航班数最少的一种有多少班、最多的一种有多少班（条数对 109+710^9+7109+7 取模）。

解题思路：分两步。第一步，反向建图从 n 跑一遍 Dijkstra，得到每个点到 n 的最短花费 price[x]。第二步，从 1 做记忆化搜索 f(x)：只沿满足 price[x] == price[y] + len 的边 x→y 转移（这条边处于某条最短路上），依次统计 n_min_price[x]（方案数）、min_flights[x]（最少航班数）、max_flights[x]（最多航班数），转移时航班数都加 1。最后输出 price[1] 与四个统计量。第一步复杂度 O((n+m)log⁡n)O((n+m)\log n)O((n+m)logn)，第二步 O(n+m)O(n+m)O(n+m)。（price 等数组与递归 f 需定义在 solve() 外。）

Planets Queries II

题目大意：n 个星球、每个星球指向一个传送目的地，q 次询问从 a 传送到 b 至少要多少次，不可达输出 -1。

解题思路：每个点出度为 1，整张图是若干棵"内向基环树"：一个环，外加指向环的若干棵树。先用快慢指针 extract_cycle 找到每个连通块的环，并把环上除入口外各点按环序标成负深度 depth[cycle[j]] = -j；再从环入口 cycle[0] 沿反图 rev_graph 做 DFS，树上的点依次标递增的 depth。核心技巧：沿反图从子节点往父节点走恰好对应一次传送，因此从 a 到 b 的传送次数就是 depth[a]-depth[b]（环上点靠预先标好的负深度保持"可见"）。所以每个点在 DFS 进入时处理挂在它身上的询问：depth[b] 有效就给 depth[a]-depth[b]，否则输出 -1。复杂度 O(n+q)O(n+q)O(n+q)。（depth、rev_graph、queries 等数组与递归 dfs 需定义在 solve() 外。）

Planets Cycles

题目大意：n 个星球、每个星球指向一个传送目的地。从某个星球出发一直传送，直到走到一个已经访问过的星球为止。对每个星球，求这条路径一共经过了多少个不同的星球（出发点也计入）。

解题思路：每个点出度为 1，连通块是一棵内向基环树。用快慢指针 find_cycle 找出环并得到环长 size，把环上的点标记 cycle[x]=true。环上任意一点出发，绕着环走一圈回到起点，一共经过 size 个不同星球，所以环上点的答案就是环长；树上的点 x 比它的父节点（指向的方向）多经过自己一个星球，即 answer[x] = answer[父节点] + 1。dfs 从环出发沿反图 rev_graph 把答案逐层传下去即可。复杂度 O(n)O(n)O(n)。

Road Reparation

题目大意：n 个城市、m 条可以修复的道路，每条有修复费用。求让所有城市连通所需的最小总费用；无法连通则输出 IMPOSSIBLE。

Road Construction

题目大意：一开始 n 个城市两两不连通。之后 m 天每天会加入一条新的路（连接两个城市），输出每天之后的连通块个数以及最大连通块的大小。

Flight Routes Check

题目大意：有向图，判断是否任意两点都能互相到达（即整张图强连通）；否则输出任意一对不可达的 (a,b)。

解题思路：若图强连通，那么 1 号必须能到达所有点、且所有点都能到达 1。所以只需分别从 1 在原图 g 和反图 rev_g 上做 DFS：visited1 记录 1 能到达的点，visited2 记录反图上 1 能到达的点（等价于原图能到达 1 的点）。若 visited1[i] 为假，说明 1 到不了 i，输出 (1,i)；若 visited2[i] 为假，说明 i 到不了 1，输出 (i,1)；全部为真才输出 YES。复杂度 O(n+m)O(n+m)O(n+m)。

Planets and Kingdoms

题目大意：有向图中，两个点在同一"王国"当且仅当它们互相可达。求强连通分量（SCC）的个数，以及每个点所属的分量编号。

解题思路：Kosaraju 算法。第一遍在原图 graph 上做 DFS，按 DFS 完成顺序把点依次加入 order（后序遍历）；第二遍把 order 逆序，在反图 graph_rev 上按顺序 DFS，每次 DFS 能访问到的点集恰好是一个强连通分量，给它分配编号 id 并让计数加 1。component[i] 记录每个点的归属。复杂度 O(n+m)O(n+m)O(n+m)。

Giant Pizza

题目大意：n 个家庭成员、m 种配料。每个人提出两个条件（+x 表示必须有配料 x，-x 表示不能有配料 x），要求每人的两个条件中至少满足一个。求一种配料选择方案（每行输出 + 或 -），否则输出 IMPOSSIBLE。

解题思路：2-SAT。每种配料 x 拆成两个文字：真（编号 x，代表 +）和假（编号 x+m，代表 -）。每人的两个愿望构成子句 (A∨B)(A \lor B)(A∨B)，等价于蕴含边 ¬A→B\neg A \to B¬A→B 和 ¬B→A\neg B \to A¬B→A，据此建图后用 Tarjan 求强连通分量：若某个 x 与 x+m 落在同一 SCC（真与假互相推出，矛盾），则不可满足。否则由于 SCC 缩点图是 DAG，编号较小的 SCC 在拓扑序上更靠后、取它更安全，于是按 sccno[x] < sccno[x+m] 决定输出 + 还是 -。复杂度 O(n+m)O(n+m)O(n+m)。（G、low、num、sccno、st、scc 等数组与递归 dfs、tarjan 需定义在 solve() 外。）

Coin Collector

题目大意：有向图里每个房间有一定数量金币，可以任选起点和终点、沿有向边前进，经过的房间金币都会被收集（每个房间至多收集一次）。求最多能收集多少金币。

解题思路：强连通分量内部任意两点互相可达，所以一个 SCC 里的金币可以全部拿完。先用 Tarjan 缩点，把每个 SCC 的金币求和得到 res[i]，再在缩点后的 DAG 上做记忆化 DP：dp[u] = max_{v\in g[u]} f(v) + res[u]（从分量 u 出发能拿到的最大金币数），答案取所有 dp 的最大值。复杂度 O(n+m)O(n+m)O(n+m)。（G、low、num、sccno、scc、res、dp 等数组与递归 dfs、tarjan、f 需定义在 solve() 外。）

Mail Delivery

题目大意：无向连通图，求从 1 号出发、经过每条边恰好一次并回到 1 号的回路（欧拉回路），输出经过的顶点序列；不存在则输出 IMPOSSIBLE。

解题思路：欧拉回路存在当且仅当每个点的度数都是偶数（图连通性由最后的边数检查兜底）。用 Hierholzer 算法：从 1 号做 DFS，每次取当前点的一条边（代码用 set 存邻点，取最小者），从两端的集合中删掉这条边后递归到对端；DFS 返回时把点压入 cycle。由于每条边恰好被删一次，走完 m+1 个顶点（边数 m 加 1）就得到回路；若 cycle.size() != m+1 说明图不连通或有孤立边，输出 IMPOSSIBLE。复杂度 O((n+m)log⁡n)O((n+m)\log n)O((n+m)logn)（set 删除是 log⁡\loglog 的）。

De Bruijn Sequence

题目大意：构造一个最短的二进制串，使它的所有长度为 n 的连续子串互不相同（即包含全部 2n2^n2n 种 n 位二进制串）。

解题思路：构造长度为 2n+n−12^n+n-12n+n−1 的 De Bruijn 序列。把"当前窗口里的 n−1n-1n−1 位状态"看成点，从状态 v 向末尾追加一位 i（0 或 1）就得到一个新的 nnn 位串 u=(v<<1)+i，其后 n−1n-1n−1 位就是下一个状态，于是每个 nnn 位串恰好对应一条边。该图每个点出度入度都为 2，存在欧拉回路；used[u] 标记每个 nnn 位串是否已经用过，DFS 贪心沿每条未用的边走，走完一条边就把追加的那位 i 写进答案。最后补上起点对应的 n−1n-1n−1 个 0，总长正好 2n+n−12^n+n-12n+n−1。复杂度 O(2n)O(2^n)O(2n)。（used、ans 与递归 dfs 需定义在 solve() 外。）

Teleporters Path

题目大意：有向图，求从 1 号出发、到 n 号结束、经过每条边恰好一次的路径（欧拉路径），输出经过的顶点序列；不存在则输出 IMPOSSIBLE。

解题思路：欧拉路径存在的条件是：除起点和终点外每个点入度等于出度，起点出度比入度多 1，终点入度比出度多 1。代码用一个小技巧：人为执行 in_degree[1]++、out_degree[n]++（相当于补一条 n→1 的假边），于是问题统一成"所有点入度等于出度"的欧拉回路，检查不通过直接 fail。之后用 Hierholzer 从 1 号出发走边（graph 存出边、pop_back 删除已走的边），最后把 cycle 反转输出。若 cycle.size() != m+1 说明没走完所有边，无解。复杂度 O(n+m)O(n+m)O(n+m)。

Hamiltonian Flights

题目大意：n 个城市、m 条单向航班（同一起终点的多条航班视为不同路线），求从 1 号出发、恰好经过每个城市一次、最后到达 n 号的路线数，对 109+710^9+7109+7 取模。

解题思路：状压 DP。ways[mask][last] 表示已访问城市集合为 mask、最后停在 last 的方案数。编号从 0 开始，初值 ways[1][0]=1（起点为 0 号）。转移枚举上一步的城市 prev：ways[mask][last]=∑prev∈maskcount[prev][last]⋅ways[mask⊕2last][prev]ways[mask][last]=\sum_{prev\in mask} count[prev][last]\cdot ways[mask \oplus 2^{last}][prev]ways[mask][last]=∑prev∈mask​count[prev][last]⋅ways[mask⊕2last][prev]，其中 count[prev][last] 是 prev→last 的重边数（重边让方案数成倍增加）。答案即 ways[(1<<n)-1][n-1]。复杂度 O(n2⋅2n)O(n^2\cdot 2^n)O(n2⋅2n)，n≤20n\le20n≤20 可行。

Knight’s Tour

题目大意：在 8×8 的国际象棋棋盘上，从给定起点出发，找一条经过每个格子恰好一次的骑士巡游路径，输出每格对应的步数表。

解题思路：DFS + Warnsdorff 启发式。在每一步，枚举所有合法走法，对每个候选格计算它"下一步还有几个可走的格子"（degree），把所有候选按 degree 升序排序，优先走选择最少的方向。直观解释：先把"出路少"的格子解决掉，避免走到后面被堵死；配合回溯保证正确性，实际运行非常快。代码里 grid[y][x] 存到达步数，走满 64 格就输出并退出。最坏复杂度指数级，但启发式下实际几乎线性。

Download Speed

题目大意：n 台电脑、m 条单向连接，每条连接有带宽上限，求从 1 号到 n 号最多能传输的带宽（即最大流）。

解题思路：直接建最大流模型：源点 1、汇点 n，每条连接建一条容量为带宽的边（反向边容量 0）。代码用的是容量缩放（capacity scaling）最大流：max_flow 从高位到低位枚举流量位 bit，每一轮反复调用 dfs(source, bit) 找一条还能容纳 bit 流量的增广路（seen 防止同一轮重复访问同一点），找到就把 bit 累加到 flow，直到本轮找不到为止；DFS 走边时更新正向边和反向边（i ^ 1 配对）。复杂度约 O(E2log⁡C)O(E^2\log C)O(E2logC)，C 为最大容量，实际运行很快。

Police Chase

题目大意：无向图，问至少拆掉多少条边能让 1 号与 n 号不连通（即边权为 1 的最小割），并输出这些要拆的边。

解题思路：每条边容量设为 1，最小割大小等于最大流，用最大流求出 k。代码用 Edmonds-Karp：bfs 沿残余容量大于 0 的边找一条增广路并返回瓶颈流量，max_flow 反复增广直到找不到为止，每次增广用 parent 回溯并更新正反向容量。求出最大流后，从 1 号在残余网络上做 DFS（capacity[u][v] > 0 才走），visited 能到达的点构成割的 S 侧；原图中恰好一端被访问、一端未被访问的边就是最小割边，全部输出。复杂度 O(n3)O(n^3)O(n3) 级别（容量为 1，增广轮次不超过点数）。

School Dance

题目大意：n 个男生、m 个女生、k 对"愿意搭档"的组合，同一对只能配对一次，求最多能配成多少对，并输出配对方案（二分图最大匹配）。

解题思路：匈牙利算法（增广路算法）。对每个男生 x 依次尝试匹配：DFS 遍历他愿意的女生 i（a[x][i] 为 1），若 i 尚未被匹配，或当前匹配她的男生 links[i] 能改配到其他女生，就把 i 让给 x 并返回成功；每轮开始前把 vis 清零，防止递归走回头路死循环。累计成功的男生数就是最大匹配数。输出方案时枚举每个女生 i，若 links[i] 非 0 就输出这对（links[i] 是匹配到的男生）。复杂度 O(nm)O(nm)O(nm)。

Distinct Routes

题目大意：有向图，每条边（传送器）最多使用一次。每天从 1 号出发沿有向边走一条路到 n 号，问最多能玩多少天，并输出每天的路线（即求边互不相交的路径的最大数量）。

解题思路：边互不相交路径的最大数量等于最大流（每条边容量 1）。先建图：每条有向边容量 1，跑 Dinic 得到最大流 k，这就是答案天数。之后还原路径：addEdge 时给边打上 orig 标记区分原始边和反向边；对每条路径，从 1 号 BFS，只走"原始边且流量已被用尽"（e.orig && e.cap == 0）的边，沿 parent 回溯出这条实际有流的路径并输出；输出后把这些边恢复成"未使用"（e.cap = 1、反向边容量清 0），相当于把这条路径从网络中删掉。重复 k 次就得到全部路线。复杂度 O(EV)O(E\sqrt V)O(EV​) 级别。
