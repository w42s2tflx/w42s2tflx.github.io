Hidden Integer

题目大意：交互程序藏有一个整数 x，满足 1≤x≤1091 \le x \le 10^91≤x≤109。每次输出 ? y，可以询问命题 y < x 是否成立，并读入 YES 或 NO；最多询问 30 次。确定答案后输出 ! x。

解题思路：对答案做二分。维护闭区间 [l, r]，表示 x 当前所有可能的取值，初始为 [1, 10^9]。当 l < r 时取 mid = (l + r) / 2 并调用 check(mid)：若返回 1，说明 mid < x，因此令 l = mid + 1；否则 x \le mid，令 r = mid。这里使用下取整中点，所以两种更新都会严格缩小区间，不会遗漏答案。

当 l = r 时，该值就是 x，按协议输出 ! l。每次询问至少将区间长度减半，而 109<23010^9 < 2^{30}109<230，因此最多 30 次询问即可确定答案。代码使用 endl 立即刷新输出，保证询问和最终答案能够及时发送给交互程序。

Hidden Permutation

题目大意：交互程序藏有一个长度为 n 的排列 a。每次输出 ? i j，可以询问 a[i] < a[j] 是否成立，并读入 YES 或 NO。在 n \le 1000、询问次数不超过 10410^4104 的条件下还原整个排列，最后输出 ! 以及所有 a[i]。

解题思路：询问只能比较两个位置上的值，不能直接得到数值，因此先将所有位置按隐藏值从小到大排列。代码用 order 保存已经处理的位置，并始终保证

a[order[0]]<a[order[1]]<⋯ .a[\text{order}[0]] < a[\text{order}[1]] < \cdots . a[order[0]]<a[order[1]]<⋯.

初始把位置 1 放入 order。依次处理位置 i = 2, 3, \ldots, n 时，在当前 order 中二分它的插入位置。搜索区间采用左闭右开形式 [lo, hi)，初始为 [0, order.size())：若 ask(i, order[mid]) 返回 YES，说明 a[i] < a[order[mid]]，插入位置不晚于 mid，令 hi = mid；否则 a[i] > a[order[mid]]，令 lo = mid + 1。循环结束后，在下标 lo 插入位置 i，order 仍按隐藏值递增。

排列包含的值恰好是 111 到 n。所有位置排好后，order[i] 对应的隐藏值就是 i + 1；由于 a 使用从 0 开始的下标，代码赋值 a[order[i] - 1] = i + 1，再按原位置输出即可。插入第 i 个位置只需 O(log⁡i)O(\log i)O(logi) 次询问，总询问数为 O(nlog⁡n)O(n\log n)O(nlogn)；当 n \le 1000 时不超过 10410^4104 次。每次询问和最终答案都使用 endl 刷新输出。

K-th Highest Score

题目大意：芬兰和瑞典各有 n 个分数，每国的分数都已从高到低排列。输出 F i 或 S i，可以查询芬兰或瑞典第 i 高的分数。需要在最多 100 次查询内求出两国共 2n 个分数中的第 k 大，并输出 ! 和答案。

解题思路：考虑合并序列的前 k 个分数。假设其中从芬兰取 x 个、从瑞典取 k - x 个，这个分配合法必须满足

0≤x≤n,0≤k−x≤n,0 \le x \le n, \qquad 0 \le k-x \le n, 0≤x≤n,0≤k−x≤n,

所以 x 的搜索范围是 [max(0, k - n), min(n, k)]。对于固定的 x，这组前缀能够保证的最低分是两侧边界的较小值，即

g(x)=min⁡(F[x],S[k−x]).g(x)=\min(F[x], S[k-x]). g(x)=min(F[x],S[k−x]).

当某一侧取 0 个时并不存在第 0 高，代码在 g 中把该侧记为 INF，使另一侧的边界值自然成为最小值；搜索范围已经保证不会出现取超过 n 个的非法分配。枚举所有合法分配时，第 k 大的答案就是 max⁡g(x)\max g(x)maxg(x)。

随着 x 增大，F[x] 单调不增，而 S[k-x] 单调不减，因此 g(x) 先不减、后不增，是单峰函数。代码在闭区间 [L, R] 上二分：比较 g(mid) 和 g(mid + 1)；若前者更小，峰值一定在右侧，令 L = mid + 1，否则令 R = mid。由于 mid < R，mid + 1 始终在合法区间内。最终 L = R，再次调用 g(L) 得到答案并输出。每轮二分至多查询 4 个分数，因为 g(mid) 和 g(mid + 1) 各至多发出两次查询；最后计算答案至多再查询 2 次，总数为 O(log⁡n)O(\log n)O(logn)，并满足 100 次限制。

Permuted Binary Strings

题目大意：交互程序藏有一个长度为 n 的排列 a。每次输出一个二进制串 b 后，会收到按该排列重排得到的串 c，其中 c[j] = b[a[j]]。需要在不超过 10 次询问内还原所有 a[j]，最后输出 ! 以及整个排列。

解题思路：固定返回位置 j 来看，每次收到的 c[j] 都来自查询串的第 a[j] 位。因此，可以给原串的每个位置编码，再从同一位置 j 的多次回复中恢复编码，从而确定 a[j]。

代码使用位置编号 1..n 本身的二进制表示作为编码。先取最小的 bits，使 2bits≥n+12^{bits} \ge n+12bits≥n+1，即代码中的 while ((1 << bits) < n + 1) bits++。第 t 次询问构造字符串 b：当位置编号 i 的第 t 个二进制位为 1 时，令 b[i - 1] = '1'，否则保持为 '0'。交互程序返回的 c[j] 因而正好是 a[j] 的第 t 个二进制位，代码将它保存到 res[t][j]。

所有询问结束后，对每个从 0 开始的返回下标 j，依次检查 res[t][j]；若该位是 '1'，就执行 v |= 1 << t。重建出的 v 就是题目中从 1 开始编号的 a[j + 1]，按顺序输出即可。由于 n≤1000n \le 1000n≤1000 时 bits 不超过 10，询问次数满足限制；构造和解码的时间复杂度均为 O(n⋅bits)O(n\cdot bits)O(n⋅bits)。代码每次输出询问和最终答案时都使用 endl 刷新。

Colored Chairs

题目大意：n 为奇数，n 把椅子首尾相接围成一圈，每把椅子是红色或蓝色。输出 ? i 可以查询第 i 把椅子的颜色。需要在最多 20 次查询内找到一对相邻且同色的椅子，并输出 ! i，其中 i 表示这对椅子中的前一把；当 i = n 时，后一把是椅子 1。

解题思路：先查询椅子 1 的颜色并记为 c1。以 c1 为起点构造一个理想的交替序列：奇数位置的期望颜色为 c1，偶数位置的期望颜色为另一种颜色，代码用 exp 计算这一期望值。为了统一处理首尾相邻，把虚拟位置 n + 1 视为椅子 1，因此该位置的实际颜色由代码直接设为 c1，不额外查询。

因为 n 是奇数，虚拟位置 n + 1 为偶数，理想交替序列要求它与 c1 异色，但它实际上就是颜色为 c1 的椅子 1，所以区间 [2, n + 1] 中必然存在实际颜色与 exp 不同的位置。代码在这个区间二分寻找一个失配边界：若 cm != exp，令 hi = mid；否则令 lo = mid + 1。当某个被查询位置与期望颜色一致时，从椅子 1 到该位置之间发生的相邻同色次数为偶数；失配时则为奇数，因此二分两端始终夹着至少一处状态变化。最终 lo - 1 与 lo 的状态不同，而相邻位置的期望颜色也不同，所以这两把椅子的实际颜色相同。

若 lo \le n，答案是相邻的 lo - 1 和 lo；若 lo = n + 1，哨兵代表椅子 1，答案就是环边界上的椅子 n 和椅子 1，输出 lo - 1 = n 仍然正确。除第一次查询椅子 1 外，二分每轮至多查询一次真实椅子；查询总数为 1+O(log⁡n)1+O(\log n)1+O(logn)，满足 20 次限制。所有交互输出均用 endl 刷新。

Inversion Sorting

题目大意：交互程序藏有一个长度为 n 的排列。每次输出区间端点 l r，程序会先翻转 [l, r]，再返回当前整个排列的逆序对数；若逆序对数变为 0，交互立即结束。需要在不超过 4n 次翻转内将排列排成升序。

解题思路：算法分为探测和排序两步。探测阶段求原排列每个前缀的逆序对数 b[i]，并通过两次相同翻转恢复原排列；排序阶段利用相邻前缀逆序对数之差，将每个元素插入已经有序的前缀。

先推导一次翻转提供的信息。长度为 len = r - l + 1 的区间中共有 len(len−1)2\frac{len(len-1)}{2}2len(len−1)​ 对元素，翻转会把每对元素的先后顺序颠倒，因此区间内部原来是逆序的数对变为顺序，原来是顺序的数对变为逆序。设翻转前、后的区间内部逆序对数分别为 involdinv_{old}invold​、invnewinv_{new}invnew​，整个排列的逆序对数分别为 invSumoldinvSum_{old}invSumold​、invSumnewinvSum_{new}invSumnew​，则

invnew+invold=len(len−1)2,invSumnew−invSumold=invnew−invold.\begin{aligned} inv_{new}+inv_{old} &= \frac{len(len-1)}{2},\\ invSum_{new}-invSum_{old} &= inv_{new}-inv_{old}. \end{aligned} invnew​+invold​invSumnew​−invSumold​​=2len(len−1)​,=invnew​−invold​.​

联立可得翻转前该区间的内部逆序对数：

invold=len(len−1)/2+invSumold−invSumnew2.inv_{old}=\frac{len(len-1)/2+invSum_{old}-invSum_{new}}{2}. invold​=2len(len−1)/2+invSumold​−invSumnew​​.

对每个 i = 2, 3, \ldots, n，第一次调用 ask(1, i) 后，前缀 [1, i] 已被翻转，返回值 newValue 是翻转后的全局逆序对数；紧接着第二次调用相同区间，将该前缀翻回原状，返回值 oldValue 是原排列的全局逆序对数。于是代码按

b[i]=i(i−1)/2+oldValue−newValue2b[i]=\frac{i(i-1)/2+oldValue-newValue}{2} b[i]=2i(i−1)/2+oldValue−newValue​

求出原排列前缀 [1, i] 的逆序对数。每轮结束后排列都恢复原状，所以不同 b[i] 对应同一个原排列。

排序阶段从 i = 2 开始，并维持前缀 [1, i-1] 已经升序。差值 x = b[i] - b[i - 1] 正是原排列中位于 a[i] 前面且大于它的元素个数。此前的排序操作只涉及位置不超过 i - 1 的前缀，不会移动原位置 i 上的元素；同时只会重排前面的元素，不改变其中有多少个值大于 a[i]，所以这个 x 在当前状态下仍然有效。由于 [1, i - 1] 已有序，这 x 个较大元素恰好占据连续区间 [i - x, i - 1]。

当 x > 0 时，代码先翻转 [i - x, i]。设这段原本为 B + a[i]，其中 B 是递增的 x 个较大元素；第一次翻转后变为 a[i] + reverse(B)。再翻转 [i - x + 1, i]，只把 reverse(B) 恢复为 B，最终得到 a[i] + B，等价于把 a[i] 插到这些较大元素之前，因此 [1, i] 变为升序。若 x = 0，a[i] 已经位于正确位置，不需要翻转。

探测每个 i 使用两次翻转，排序每个 i 最多使用两次，共不超过 4(n−1)4(n-1)4(n−1) 次；若某次翻转后逆序对数为 0，ask 会立即执行 exit(0)，这正是交互协议要求的结束方式。n = 1 时，代码调用 ask(1, 1)，逆序对数为 0 并直接结束。除交互程序自身处理逆序对的时间外，代码的计算复杂度为 O(n)O(n)O(n)。
