Weird Algorithm

题目大意：给定一个正整数 n（n≤106n \le 10^6n≤106），反复执行以下操作：若 n 是偶数，则将它除以 2；若 n 是奇数，则将它乘以 3 再加 1。按顺序输出从初始值到 1 的整个变化过程。

解题思路：直接模拟。每轮先输出当前的 n；如果 n 已经等于 1，就结束循环，否则根据奇偶性更新它。中间结果可能超出 int 的范围，因此用 ll 存储。时间复杂度为 O(迭代次数)O(\text{迭代次数})O(迭代次数)。

Repetitions

题目大意：给定一个只含 A、C、G、T 的字符串（长度 n≤106n \le 10^6n≤106），求由同一字符连续组成的最长子串长度。

Increasing Array

题目大意：给定一个长度为 n 的数组（n≤2×105n \le 2 \times 10^5n≤2×105，元素 ≤109\le 10^9≤109）。每次操作可以把任意元素加 1，求使数组变为不下降序列所需的最少操作次数。

解题思路：从左到右贪心处理。若 x[i] < x[i - 1]，为了满足不下降条件，x[i] 至少要增加到 x[i - 1]，因此把差值 x[i - 1] - x[i] 加入答案，并令 x[i] = x[i - 1]。增加得更多只会浪费操作并提高后续元素必须达到的下界，所以取恰好相等最优。时间复杂度为 O(n)O(n)O(n)。

Permutations

题目大意：构造一个 111 到 n 的排列（n≤106n \le 10^6n≤106），使任意两个相邻数之差都不等于 1。若无法构造，输出 NO SOLUTION。

解题思路：n=1n=1n=1 时直接输出 1，n=2n=2n=2 或 n=3n=3n=3 时无解。对 n≥4n \ge 4n≥4，先按升序输出所有偶数，再按升序输出所有奇数。同为偶数或同为奇数的相邻两数之差都是 2；两段交界处是最大的偶数与 1，其差也不会是 1，因此构造合法。时间复杂度为 O(n)O(n)O(n)。

Number Spiral

题目大意：无限方格中按数字螺旋的规律填入正整数。每组输入依次给出行坐标 x 和列坐标 y（x,y≤109x, y \le 10^9x,y≤109），求第 x 行、第 y 列上的数字。

解题思路：格子所在层数由 max(x, y) 决定，代码按照行坐标 x 与列坐标 y 的大小分两种情况：

  • 若 x≥yx \ge yx≥y，格子位于第 x 层的下边界。x 为奇数时，从 (x−1)2+1(x-1)^2+1(x−1)2+1 起沿底边向右递增，答案为 (x−1)2+y(x-1)^2+y(x−1)2+y；x 为偶数时，从右下角的 x2x^2x2 向左递减，答案为 x2−y+1x^2-y+1x2−y+1。
  • 若 y>xy > xy>x，格子位于第 y 层的右边界。y 为奇数时，从右下角的 y2y^2y2 向上递减，答案为 y2−x+1y^2-x+1y2−x+1；y 为偶数时，从 (y−1)2+1(y-1)^2+1(y−1)2+1 起沿右边向下递增，答案为 (y−1)2+x(y-1)^2+x(y−1)2+x。

坐标最大为 10910^9109，平方结果需要用 ll 存储。每组询问的时间复杂度为 O(1)O(1)O(1)。

Two Sets

题目大意：把 111 到 n 的所有整数（n≤106n \le 10^6n≤106）分成两个集合，使两个集合的元素和相等。若可行，输出任意一种划分；否则输出 NO。

解题思路：总和 s=n(n+1)/2s=n(n+1)/2s=n(n+1)/2 必须是偶数，否则不可能平分。若 s 为偶数，就令 res = s / 2，从大根堆中按 n,n−1,…,1n, n-1, \ldots, 1n,n−1,…,1 的顺序取数：若当前数 x <= res，就将 x 放进集合 a 并令 res -= x；否则放进集合 b。

Trailing Zeros

题目大意：求 n!n!n! 的十进制表示末尾有多少个连续的 0（n≤109n \le 10^9n≤109）。

解题思路：一个末尾 0 来自一个因子 10=2×510=2\times510=2×5。在 n!n!n! 中因子 2 比因子 5 多，因此只需统计因子 5 的个数。555 的倍数至少贡献一个 5，252525 的倍数还会多贡献一个，依此类推，答案为

⌊n5⌋+⌊n25⌋+⌊n125⌋+⋯ .\left\lfloor\frac n5\right\rfloor+ \left\lfloor\frac n{25}\right\rfloor+ \left\lfloor\frac n{125}\right\rfloor+\cdots. ⌊5n​⌋+⌊25n​⌋+⌊125n​⌋+⋯.

代码每轮把 n / 5 加入答案，再令 n /= 5，直到 n<5n < 5n<5。时间复杂度为 O(log⁡n)O(\log n)O(logn)。

Coin Piles

题目大意：有 t 组询问，每组给两堆硬币数量 a、b（a,b≤109a, b \le 10^9a,b≤109）。每次操作必须从一堆取走 1 枚、从另一堆取走 2 枚。判断能否经过若干次操作将两堆同时取空。

解题思路：设“从第一堆取 1 枚、第二堆取 2 枚”的操作执行 x 次，另一种操作执行 y 次，则

a=x+2y,b=2x+y.\begin{aligned} a&=x+2y,\\ b&=2x+y. \end{aligned} ab​=x+2y,=2x+y.​

Palindrome Reorder

题目大意：重新排列给定字符串（长度 n≤106n \le 10^6n≤106）的全部字符，使结果成为回文串。若可行，输出任意一种结果；否则输出 NO SOLUTION。

解题思路：统计每个字符的出现次数。回文串中除中心位置外，所有字符都必须成对出现，因此出现奇数次的字符不能超过一个。构造时按字母顺序输出每个字符的一半，形成左半部分；若存在奇数次字符，将它放在中心；最后按相反顺序输出每个字符的一半，形成右半部分。左右两部分互为镜像，因此结果一定是回文串。时间复杂度为 O(n)O(n)O(n)。

Gray Code

题目大意：构造 n 位格雷码（n≤16n \le 16n≤16），即按某种顺序输出全部 2n2^n2n 个 n 位二进制串，使任意相邻两个串恰好有一位不同。

Tower of Hanoi

题目大意：有 3 根柱子，需要把 n 个大小不同的圆盘（n≤16n \le 16n≤16）从 1 号柱全部移动到 3 号柱，可以借助 2 号柱。每次只能移动一个圆盘，且大圆盘不能放在小圆盘上。输出最少移动次数及每一步操作。

解题思路：用递归函数 move(n, a, b, c) 表示借助柱 c，把 n 个圆盘从柱 a 移到柱 b。先把上方 n−1n-1n−1 个圆盘从 a 移到 c，再把最大的圆盘从 a 移到 b，最后把 n−1n-1n−1 个圆盘从 c 移到 b。每个圆盘都按这一过程移动，得到的步数满足 T(n)=2T(n−1)+1T(n)=2T(n-1)+1T(n)=2T(n−1)+1，即 2n−12^n-12n−1。这也是最少步数：最大圆盘至少移动一次，而移动它之前、之后都必须把 n−1n-1n−1 个小圆盘整体搬到另一根柱上，各至少 T(n−1)T(n-1)T(n−1) 步，故 T(n)≥2T(n−1)+1T(n)\ge 2T(n-1)+1T(n)≥2T(n−1)+1，与构造步数的递推一致。代码把每次移动存入全局数组 moves，最后统一输出。时间复杂度为 O(2n)O(2^n)O(2n)。

Raab Game I

题目大意：两名玩家各有一套点数为 111 到 n 的牌。每轮双方各出一张未使用的牌，点数较大者得 1 分，相同则都不得分。给定最终得分 a、b，判断结果是否可能；若可能，构造双方的出牌顺序。例：n = 5, a = 2, b = 1 时，第一名按 1 2 4 5 3 出牌即可（前两轮平局、中间两轮胜、最后一轮负）。

解题思路：每轮至多产生 1 分，所以首先必须满足 a+b≤na + b \le na+b≤n。代码令第二名玩家按 1,2,…,n1, 2, \ldots, n1,2,…,n 出牌，并为第一名玩家构造排列 v：

  • 前 n−a−bn-a-bn−a−b 轮放入 1 到 n−a−bn-a-bn−a−b，双方平局；
  • 接下来的 a 轮放入 n−a+1n-a+1n−a+1 到 nnn，这些牌都大于第二名玩家在对应轮次的牌，第一名玩家获胜；
  • 最后的 b 轮放入 n−a−b+1n-a-b+1n−a−b+1 到 n−an-an−a，这些牌都小于第二名玩家在对应轮次的牌，第二名玩家获胜。

三个区间互不重叠，并恰好覆盖 111 到 n。并非所有满足 a+b≤na + b \le na+b≤n 的输入都能通过上述比较，例如一方得 0 分而另一方得正分时无解，因此代码实际逐轮比较 v[i] 与 i，从 a、b 中扣除构造出的胜局；只有二者都变为 0 时才输出方案。时间复杂度为 O(n)O(n)O(n)。

Mex Grid Construction

题目大意：构造一个 n×nn\times nn×n 的网格。每个格子的值等于其左侧同一行与上方同一列中没有出现过的最小非负整数，即这些已有数的 mex。例：n=3n=3n=3 时输出为 0 1 2 / 1 0 3 / 2 3 0。

解题思路：代码先把所有 a[i][j] 初始化为 -1，再按行从左到右填表。处理 (i, j) 时，它实际收集的是当前行 a[i][1..j] 和当前列 a[1..i][j]：其中 a[i][j] 尚未填写，所以会被收集两次，值都为 -1；其余元素正好是题目要求的左侧和上方已填数字。由于 mex 只关心非负整数，这两个 -1 不影响结果。

将收集到的 v 排序后，从 p = 0 开始扫描：遇到 item == p 就令 p++，最终得到最小未出现的非负整数。左侧与上方真正参与 mex 的格子共有 (j−1)+(i−1)(j-1)+(i-1)(j−1)+(i−1) 个，因此 mex 至多为 i+j−2i+j-2i+j−2，全局至多为 2n−22n-22n−2。每个格子最多排序 O(n)O(n)O(n) 个数，总时间复杂度为 O(n3log⁡n)O(n^3\log n)O(n3logn)。

Grid Coloring I

题目大意：给定一个 n×mn\times mn×m 网格，每个格子的原颜色是 A 到 D 之一。需要重新为每个格子选择一种颜色，使它与原颜色不同，并且任意上下左右相邻格子的颜色不同。输出一种方案；若不存在则输出 IMPOSSIBLE。

解题思路：按从上到下、从左到右的顺序填色。处理 (y, x) 时，只有上方和左侧格子已经确定，只需避开原颜色、上方颜色和左侧颜色，最多排除 3 种颜色。可选颜色共有 A、B、C、D 四种，因此一定至少剩下一种，代码选择按字母顺序遇到的第一种。之后填右侧和下方格子时也会避开当前颜色，所以最终所有相邻格均不同，方案始终存在。时间复杂度为 O(nm)O(nm)O(nm)。

Digit Queries

题目大意：将所有正整数依次拼接成无限字符串 123456789101112...。每次询问给定一个从 1 开始的位置 n（n≤1018n \le 10^{18}n≤1018），求该位置上的数字。

解题思路：按整数位数分块。k 位数共有 w 个，它们贡献 w⋅kw \cdot kw⋅k 个字符；代码从 1 位数开始，只要查询位置 n 超过当前块，就减去整块长度，并将 v 增加 w，使 v 始终表示当前块之前共有多少个整数。循环结束后，a = (n + k - 1) / k 是目标字符位于当前块的第几个整数，故该整数为 z = v + a；b = (n - 1 + k) % k 是字符在 z 中的从 0 开始下标。转成字符串后输出 res[b] 即可。全程使用 ll，时间复杂度为 O(log⁡n)O(\log n)O(logn)。

String Reorder

题目大意：重新排列给定字符串的全部字符，使任意两个相邻字符都不同，并在所有合法排列中字典序最小。若无法做到，输出 -1。

解题思路：若剩余字符串长度为 length，某字符还剩 v[i] 个，要把这些相同字符隔开，至少需要 v[i] - 1 个其他字符，因此必须满足 2v[i]−1≤length2v[i]-1\le length2v[i]−1≤length。代码用 check(length) 检查所有字符是否都满足这一条件；该条件也是充分的。反证：若某步贪心无字可放，则放置任意剩余字符后条件都被破坏，破坏者只能是满足 2v[c]−1=length2v[c]-1=length2v[c]−1=length 的字符 c（两个字符同时满足会超出总长度，不可能）；而放置这个 c 本身是合法的（2(v[c]−1)−1=length−2≤length−12(v[c]-1)-1=length-2\le length-12(v[c]−1)−1=length−2≤length−1），唯一例外是 c 恰为上一位字符。这种状态不可达：上一步放置 c 前其计数为 v[c]+1v[c]+1v[c]+1，要通过当时的 check 需要 2(v[c]+1)−1≤length+12(v[c]+1)-1\le length+12(v[c]+1)−1≤length+1，与 2v[c]−1=length2v[c]-1=length2v[c]−1=length 矛盾。因此初始条件成立时贪心必能构造完成。

构造时从左到右确定每一位。对当前位置按 A 到 Z 尝试字符，跳过数量为 0 或与上一位相同的字符。暂时将候选字符的数量减 1，再检查剩余部分是否仍可构造；若可行，就确定该字符，否则恢复数量并尝试下一个。每一步都选择字典序最小的可行字符，因此最终结果字典序最小。每个位置最多尝试 26 个字符，每次检查 26 种计数，时间复杂度为 O(262n)O(26^2n)O(262n)。

Grid Path Description

题目大意：在 7×77\times77×7 网格中，从左上角出发，经过恰好 48 步到达左下角，并且不能重复经过格子。输入一个长度为 48 的路径描述串，其中 D、U、R、L 表示固定方向，? 可表示任意方向。求符合描述的合法路径数。

解题思路：直接 DFS 枚举每一条可能的路径会超时，需要剪枝，主要有三个优化：

  1. 已经到达终点（左下角）但还没走满 48 步，直接返回，因为题目要求路径必须走满 48 步。

  2. 当前格子的上下都走不了、但左右还能走时，网格会被分成互不相通的两块，每块里都还有没走过的格子，说明永远走不完，直接返回。图示中 1 是当前位置，0 是还没走过的格子，# 是已经走过或不能走的位置：
